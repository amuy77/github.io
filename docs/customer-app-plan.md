# お客さん用アプリ（計画のみ・まだ作らない）

店主の判断（2026-10-06）: お客さん用はまだ使わないので、実装はせず計画として置いておく。始めるときはこの文書から。

## 決まっていること
- **別アプリ**（同じリポジトリ、部品は共通。アイコン・名前・マニフェストを別に）。LaRa をベースに、仕様は店側と分ける。3D（three.js）はお客さんの端末に配らない。
- **Planner はアプリの中に取り込む**（お店側は連携のまま）。
- **AI 相談はお客さんには出さない**（Claude API は有料のため）。
- URL は当面 `amuy77.github.io/github.io/` の下、リリース時に独自ドメイン（年 1,500 円前後〜）。

## 機能（MVP → 後で）
1. **公開メニュー**: レシピをそのまま見せない（原価・手順が入っているため）。`recipes` に `is_public` / `public_blurb` / アレルギーを足し、オンにした品だけ `public_menu` ビューで公開（価格は `recipes.price` を使う。段階 1 で追加済み）。ログイン前でも見られる → 会員になる入口。
2. **ログイン**: Google（または LINE）を主に。Supabase 内蔵メールは送信数が少ないので補助。
3. **会員証**: 30 秒で変わる QR（`member_no` ＋ HMAC）。お店側にスキャン画面（`BarcodeDetector`、非対応は `jsQR`）。ポイント・スタンプの付与は必ず Edge Function（`checkin`）経由、1 日 1 回まで。圏外でも会員番号は表示。ランク名は LaRa の三日月にちなんで「月の満ち欠け」。
4. **スタンプ → LaRa から小包**（服・家具・手紙）。お金での購入やガチャはなし。期限切れ・連続ログインの強制なし。
5. **お客さんの Planner**: お店のカレンダー（定休日・限定メニュー・イベント `shop_events`）、わたしの予定（次に来る日）。予約・取り置きは後回し。
6. **毎日開きたくなる仕組み（義務にしない）**: LaRa の部屋・今日の小さな発見（取り逃しても損なし）・季節イベント・お店の今日のメニューが黒板に出る・任意のプッシュ通知（iOS はホーム画面追加が前提）。
7. **Google Wallet**（無料で可能、後回し）。Apple Wallet は有料の開発者登録が必要なので不可。

## データとセキュリティ（土台）
- 段階 1 で `shops` / `shop_members` を追加済み（データは人ごとのまま）。
- お客さん用に `profiles(user_id, role: customer)`、`members(user_id, shop_id, member_no, points, stamps, qr_secret)`、`visits`、`rewards`、`redemptions`。
- `check_allowed_email` は「許可リストの人＝スタッフ、それ以外＝お客さん」に変える。**店側の全テーブルの RLS に「スタッフであること」を足すのが最重要**（足さないとお客さんアカウントが店側の表に行を作れてしまう）。
- お客さん向けの写真は別バケット（レシピ原本の写真は公開しない）。
- 取るのはメールと表示名だけ。退会で全部消える。最初に利用目的の同意。

## 段階

4. 拡張: ランク特典・Google Wallet・予約

## お店側から持ってこられるもの
- **お気に入りのお店（ノートの「📍 お店」）**: `src/features/places/` にまとめてある。Google マップのリンクの読み取り（`mapsUrl.ts`）、地図（`PlaceMap.tsx`・国土地理院の淡色地図）、傾向の集計（`trends.ts`）、一覧の行・傾向の画面はそのまま使える。
  `places` 表は人ごと（RLS は自分の行だけ）なので、お客さんも自分のアカウントで同じ表に溜められる。入れるときは上の「スタッフであること」の RLS の見直しと合わせて、お客さんが使ってよい表として残す。
